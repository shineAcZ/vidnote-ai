# VidNote AI Firefox 版

Firefox Manifest V3 测试版（0.1.17）。支持读取视频字幕、点击字幕跳转、调用 DeepSeek 或其他 OpenAI-compatible AI 生成带时间戳的 Markdown 笔记，并导出为 Obsidian Media Extended 兼容文件。

## 快速安装测试

1. 在 Firefox 地址栏打开 `about:debugging`。
2. 点击“此 Firefox”。
3. 点击“临时载入附加组件”。
4. 选择本目录中的 `manifest.json`，也可以直接选择打包好的 ZIP/XPI。
5. 打开 Bilibili 或 YouTube 视频页面。
6. 点击工具栏上的 VidNote AI 按钮，打开侧边栏。

临时安装会在 Firefox 重启后消失。要让普通用户永久安装，需要把 XPI 提交 Mozilla Add-ons 签名；未签名 XPI 通常不能永久安装到正式版 Firefox。

## 第一次使用

1. 打开侧边栏的“设置”。
2. 填写 DeepSeek API 密钥。
3. 默认 API 地址为 `https://api.deepseek.com`，默认模型为 `deepseek-v4-flash`。
4. 点击“测试连接”。
5. 打开“完整字幕”，选择字幕语言并读取；也可以导入 `.srt` 或 `.vtt`。
6. 打开“AI 笔记”，选择提示词后开始生成。

## 已包含功能

- Bilibili、YouTube 字幕读取。
- 本地 SRT/VTT 导入。
- 完整字幕列表、搜索、当前播放高亮。
- 点击字幕及笔记时间戳跳转视频。
- DeepSeek 与其他 OpenAI-compatible Chat Completions API。
- 流式输出、运行时间、任务阶段和字幕块进度。
- 暂停、继续、自动重试及部分结果保存。
- 详尽笔记、精简总结和自定义提示词。
- IndexedDB 本地任务、字幕和笔记存储。
- 安全 Markdown 预览。
- Obsidian Media Extended 兼容导出。
- DeepSeek 思考模式开关，以及 `high` / `max` 思考强度。
- 字幕块有限并发生成，可由用户设置 1–2500 个并发请求。

## 数据与权限说明

Firefox 140 及更高版本会显示数据传输声明：

- `authenticationInfo`：用户填写的 API 密钥会作为认证信息发送给用户选择的 AI 服务商。
- `websiteActivity`：视频网址和标题会用于笔记来源信息。
- `websiteContent`：用户选择的视频字幕会发送给 AI 生成笔记。

这些数据不会发送给插件开发者，也没有遥测或广告服务。API 密钥仅保存在 Firefox 的扩展本地存储中，不使用同步存储，不注入视频网页，不写入日志。

## Obsidian 导出格式

内部时间标记：

```markdown
{{t:4|00:00:04}}
```

导出后：

```markdown
[00:00:04](obsidian://mx-open?url=https%3A%2F%2Fwww.bilibili.com%2Fvideo%2FBV123&t=4)
```

## 当前测试版边界

- 最低版本设置为 Firefox 140。
- YouTube 页面桥接和 Bilibili 最新字幕接口需要在实际登录环境中验证。
- 当前只支持 OpenAI-compatible `/chat/completions` 协议。
- 关闭侧边栏会安全暂停当前 AI 网络请求；再次打开后可从已完成字幕块继续。
- 本包尚未经过 Mozilla Add-ons 签名。

## 0.1.1 修复

- 将 Bilibili 字幕 CDN 下载移到扩展后台，修复 Firefox Manifest V3 内容脚本跨域请求触发 `NetworkError when attempting to fetch resource`。
- 增加 `*.hdslb.com` 字幕 CDN 权限。
- YouTube 字幕下载遇到网页 CORS 限制时自动回退到扩展后台。

## 0.1.2 修复

- 优先使用 Bilibili 播放器当前实际加载的字幕资源。
- 优先尝试新版 `/x/player/wbi/v2` 播放器数据接口。
- 检测“几乎全是音乐”或“只覆盖视频开头”的异常字幕轨，不再把它当成完整字幕。
- 异常时自动比较播放器已经加载的其他字幕资源并选择内容更完整的版本。

## 0.1.3 改进

- 播放同步只高亮当前字幕，不再自动抢回用户的滚动位置。
- 增加固定播放位置指示条，显示当前时间和视频进度；点击后才定位当前字幕。
- 打开侧边栏后自动读取字幕；已有缓存立即显示，没有缓存时自动下载推荐字幕轨。
- “设置”中可以关闭自动读取；关闭后新视频需要手动点击“读取”。
- 笔记和任务进度继续保存在 IndexedDB，并在笔记工具栏明确显示保存状态。

## 0.1.4 改进

- 设置中增加 DeepSeek 思考模式开关，可选择“高”或“最大”思考强度。
- 请求按 DeepSeek 官方格式发送 `thinking.type` 和 `reasoning_effort`。
- 思考阶段显示“AI 正在思考”，但不会显示或保存模型内部推理文本。

## 0.1.5 改进

- 字幕分块改为并行生成，结果按原字幕块序号归位，不会因完成顺序不同而打乱笔记。
- 设置中增加 1–2500 的并发请求数，默认值为 8，实际并发不会超过剩余字幕块数量。
- HTTP 429/503 会按服务端 `Retry-After` 或指数退避自动重试，并动态把实际并发减半。
- 持续触发限额时自动暂停任务，保留已完成字幕块，稍后可以继续。
- 进度区显示当前活动请求数和动态并发上限。

## 0.1.6 改进

- 并行任务详情逐块显示等待、连接、思考、生成、重试、完成或失败状态，以及时间范围、字符数、耗时和重试次数。
- 修复任务已经完成后，延迟的流式预览仍把标题覆盖成“正在生成”的问题。
- Markdown 预览支持表格、表头对齐和横向滚动。
- 表格与正文中的内部时间标记、Obsidian 时间链接和普通 `HH:MM:SS` 均可点击跳转。
- 导出时会把 AI 偶尔生成的普通时间文本自动转换为 Media Extended 兼容链接。

## 0.1.7 改进

- 修复内部时间标记中的 `|` 被 Markdown 表格误识别成分列符，导致表格错列和跳转标记损坏的问题。
- 加强表格边框、表头底色、行分隔和横向滚动，让表格结构更清晰。
- 新生成笔记会把普通时间和 Obsidian 时间链接统一为内部时间标记，预览只显示一种时间按钮样式。
- 同一视频支持保存多份笔记；最新笔记默认展开，其他笔记折叠显示。
- 每份笔记可以单独复制、导出或删除，删除时同步清理对应的生成任务。
- 重新生成时旧笔记继续保留，新任务在独立预览区输出，完成后再加入已保存笔记列表。

## 0.1.8 改进

- DeepSeek 默认关闭思考模式；从旧设置首次升级时也会切换为关闭，之后仍可由用户手动开启。
- DeepSeek 默认最大输出从 8,192 提高到 384,000 Token，匹配 V4 的 384K 最大输出能力。
- 默认字幕块从 9,000 提高到 30,000 字符，可设置到 800,000；普通视频减少碎片，长视频继续并发。
- 最终合并单组容量从 42,000 提高到 480,000 字符，以利用 1M 上下文并减少多轮压缩。
- 读取 `finish_reason`；遇到 `length` 不再直接当作完成，而是最多自动续写两次并拼接结果。
- 对内容安全停止和推理资源不足提供明确状态与相应的停止或重试处理。
- 设置中增加日间、夜间和跟随系统三种主题，切换后立即保存。

## 0.1.9 改进

- 提示词模板增加“一次性生成”策略开关，可由用户为任意自定义模板开启或关闭。
- 一次性模式会把完整字幕只发送一次，不分块、不并发，也不执行最终合并。
- 新增“一次性详尽视频笔记”和“一次性精简视频总结”两份内置模板。
- 旧版用户会自动获得两份新内置模板，已有自定义模板保持分块模式不变。
- 开启一次性模式后，提示词编辑器会隐藏不再使用的最终合并提示词，并将主提示词标为“一次性生成提示词”。
- 生成页面会明确提示当前模板使用一次性还是分块并发策略。

## 0.1.11 改进

- 修复带 `exp=xpe` 且缺少 `pot` 令牌的新版 YouTube 字幕地址持续返回空正文的问题：优先读取 YouTube 页面原生文字稿接口，并回退复用播放器实际加载的字幕地址。

## 0.1.12 改进

- 内容导航中的 Markdown `#锚点` 链接可在当前笔记内平滑跳转到对应标题，跳转后短暂高亮定位。
- 为每份已保存笔记生成独立标题锚点，避免多份笔记出现同名标题时跳错位置。
- 标题增加可复制的锚点入口，并优化导航链接、标题和当前位置样式。
- 代码块支持语言标签、独立背景、横向滚动和一键复制，代码内容继续进行 HTML 安全转义。
- 补全普通链接、粗体、斜体、删除线、高亮、行内代码、引用、分隔线和任务列表等常用 Markdown 样式。

## 0.1.13 改进

- 修复标签页或视频快速切换时，较慢的旧页面响应可能覆盖当前视频状态的问题。
- 所有网页字幕请求都会携带预期页面身份；读取前后视频不一致时立即丢弃结果。
- 点击“开始生成”后会重新获取当前标签页与视频信息，并重新读取当前选择的字幕轨；成功后才创建 AI 任务。
- 生成前字幕读取失败、字幕无效、视频已经切换或找不到对应字幕轨时，不再回退使用旧字幕。
- 本地导入字幕会核对所属视频；切换视频后要求重新导入，避免把旧文件用于新视频。
- 保存 API 设置后自动测试接口，并分别提示“设置已保存且接口可用”或“设置已保存但自动测试失败”。

## 0.1.14 改进

- 修复 Firefox 与 Chromium 设置表单的默认最大输出和字幕块大小不符合 HTML 数字步进约束，导致点击“保存设置”时提交被浏览器静默拦截的问题。
- 数字输入改为允许任意范围内整数，默认配置现在可以直接保存。
- 设置表单改用插件内校验；API 地址、模型和高级数值不正确时会在表单底部显示明确原因，不再表现为按钮无反应。
- 增加默认配置可提交的自动化回归测试，防止以后调整默认值时再次引入步进冲突。

## 0.1.15 改进

- 默认生成策略改为整份字幕一次生成；新建自定义提示词时也默认采用该策略。
- 提示词策略选项改为“使用分段生成策略”，只有主动开启时才分段并发并执行最终合并。
- 内置模板重新排序：前两项为“详尽视频笔记、精简视频总结”，后两项为“分段·详尽视频笔记、分段·精简视频总结”。
- 升级时按稳定的内置模板 ID 自动迁移名称、策略和顺序，同时保留用户修改过的提示词正文及所有自定义模板策略。
- 提示词选择器对未带前缀的自定义分段模板显示“· 分段”，避免误判生成方式。

## 0.1.16 改进

- Firefox 的 YouTube 页面桥接改为清单声明的 `MAIN` 页面环境直接注入，与 Chromium 行为对齐，避免动态脚本注入和隔离环境差异。
- 页面桥接提前到 `document_start`，并扩大、持续观察资源记录，减少字幕请求被性能记录淘汰的情况。
- 捕获播放器通过 Fetch 或 XHR 已经成功取得的字幕正文；带 `pot` 等短期令牌、无法重复请求时可直接复用已返回内容。
- 增加只针对 YouTube `/api/timedtext` 的内存网络观察回退，为 Worker 等页面拦截器看不到的请求保留实际有效 URL。
- 每个标签页最多临时保存 40 个字幕 URL，关闭标签页自动清理，不保存 Cookie、请求头或响应数据。
- 压缩重复失败原因，避免错误提示被大量“返回空字幕”淹没。

- 优先在 YouTube 页面环境中读取字幕，失败后再使用内容脚本和后台请求回退。
- 同时兼容 YouTube JSON3、WebVTT 和 XML 字幕格式。
- YouTube 没有返回字幕时显示可操作的中文提示，不再暴露底层 JSON 解析错误。
